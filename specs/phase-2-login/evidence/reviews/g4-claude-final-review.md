## Verdict: 1 finding (1 blocking)

**Finding 1 (blocking): PRODUCT.md and TECH.md's own invariants (14, 97) and user-story text described behavior the shipped code no longer has, and the gap is security-relevant.**

The M4 collection-fetch pivot (`ARCHITECTURE.md`'s decision log, 2026-08-15 entry) correctly changed the header's name-fetch from `GET /users/<id>.json` to `GET /users.json` (the whole collection) plus client-side matching, because the real database serves no per-id path. That decision is reasoned and recorded in `ARCHITECTURE.md`. But `specs/phase-2-login/PRODUCT.md` - the actual numbered-invariant acceptance criteria - and `specs/phase-2-login/TECH.md` were never amended to match, and stated things that were now false: invariant 14 said "the collection - the thing that carries every plaintext password - is never fetched by this phase at all, in or out of the window"; invariant 97 said the header "fetches a single record rather than the collection"; TECH.md's file tree still described the deleted `userResourcePath.ts`, and its test-map entries for invariants 13/14/97/128/18a instructed "no request to `/users.json` or any collection form, ever."

Each milestone's own review checked its diff against `ARCHITECTURE.md` (which was updated) but not against `PRODUCT.md`/`TECH.md` (which were not), so the contradiction crossed every milestone boundary unnoticed - exactly the kind of seam-level gap a per-milestone review structurally cannot catch on its own.

Independently confirmed by the Codex second opinion (`g4-codex-final-review.md`, finding 1, also blocking), which additionally found a second, unrelated blocking issue: `routeDefinitions.test.ts`'s structural guard test read a lazy route's static `loader` property, which is always `undefined` for a lazy route regardless of what its `lazy()` callback resolves to - since every route in this codebase is lazy, the test could never actually catch an unguarded loader added inside one, despite its own comment claiming it would.

**Disposition:** Both fixed (commit `700634a`). PRODUCT.md invariants 14, 18a and 97 amended to describe the collection-fetch reality with the trade-off named explicitly (the collection is already public and unauthenticated-fetchable regardless of this app, so the app's own fetch widens a signed-in visitor's own audit surface rather than granting a new party access to previously-private data). TECH.md's file tree, narrative and test-map entries amended to match. The structural guard test rewritten to resolve each child's `lazy()` callback and inspect the real result, verified via a differential check (temporarily added an unguarded loader inside a lazy callback, confirmed the fixed test failed, reverted). A third, non-blocking Codex finding (a resolved user id logged to console in the live-smoke suite) was also fixed in the same commit.
