## Answers to review questions

- **Correctness (replace-vs-push branching, current-entry comparison)**: Correct. React Router's data router runs loaders *before* committing `history.push`/`.replace` for client-side (in-app) navigations, but for a full document load, a reload, or a POP (Back/Forward), the browser has already updated `window.location` before the loader runs. `requireSession.ts:22-31` and `redirectSignedInVisitor.ts:15-24` both exploit exactly this: comparing `window.location.pathname+search` to the guarded request's own `pathname+search` correctly distinguishes "the guarded URL is already the current entry" (direct load/reload/POP -> `replace()`, avoiding a re-enterable stale entry) from "the guarded URL is an in-app push target" (`redirect()`, preserving the referring entry for Back).
